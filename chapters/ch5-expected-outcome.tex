% CHAPTER 5: EXPECTED OUTCOME AND FUTURE RECOMMENDATIONS
\proposalchapter{Expected Outcome and Future Recommendations}

\section{Expected Outcome}

At the end of the project, the following are expected to be delivered:
\begin{enumerate}
  \item A working web-based bus ticket booking system with separate access for passengers, bus operators, and administrators, protected by secure login.
  \item A search module that finds buses by origin, destination, and travel date, and sorts the results by price or departure time.
  \item A seat selection and booking module with a live seat map and a temporary seat-locking mechanism that prevents double booking, tested with simultaneous booking requests.
  \item A fare calculation module that supports route-based pricing and special pricing rules, such as peak-season fares.
  \item A booking, cancellation, and booking-history workflow with online payment through eSewa, where a booking is confirmed only after the payment is verified.
  \item Reports for operators and administrators on bookings, revenue, and seat occupancy.
\end{enumerate}

In addition, the project will deliver complete documentation, including the requirement analysis, design diagrams, and test results, and the source code managed in a Git repository. The system will be a working application, demonstrated with sample data.

\section{Future Recommendations}

The system can be extended in the following ways:
\begin{enumerate}
  \item Live payments through eSewa with a registered merchant account, and other payment options.
  \item Email and SMS notifications for booking confirmation and changes to a trip.
  \item Live bus tracking using GPS.
  \item A native mobile application.
  \item Testing and tuning for a large number of simultaneous users.
  \item Analytics that help operators decide on schedules and fares, such as demand and occupancy trends.
\end{enumerate}
